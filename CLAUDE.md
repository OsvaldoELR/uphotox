# Uphotox

SaaS to run a photography studio. next-forge v6 monorepo (Turborepo + Next.js 16) with these deviations. Generic next-forge docs and skills assume the originals, so prefer this file when they disagree:

- **Database:** Supabase Postgres via supabase-js, not Prisma. Clients live in `packages/database` (`server.ts`, `client.ts`, `admin.ts`, `proxy.ts`). Schema changes are SQL migrations in `packages/database/supabase/migrations`, created with `npm run db:new -- <name>`, applied with `npm run db:push`, then `npm run db:types` to regenerate `packages/database/types.ts` (never hand-edit it once generated). After schema changes run `npx supabase db advisors --linked` from `packages/database`. The Supabase MCP server (`.mcp.json`, scoped to project `cdkosqookglkyrjazmho`) is for reading data, logs, advisors and docs; schema changes still go through migration files, never through the MCP's `apply_migration` or DDL in `execute_sql`.
- **Auth:** Supabase Auth, not Clerk. `auth()` / `currentUser()` from `@repo/auth/server`; server actions in `packages/auth/actions.ts`; route guard in `packages/auth/proxy.ts`. Supabase errors are shown through `authErrorMessage()` (`packages/auth/errors.ts`, Spanish by error code), never raw. The account emails (Confirm signup, Reset password) are Spanish templates in Supabase whose links go to `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=…` so they work in any browser; the default `{{ .ConfirmationURL }}` (PKCE `/auth/callback`) only works in the browser that asked. Reference copies and how to change them: `docs/supabase-auth-emails/`. Signing up with an address that already has a confirmed account returns a user with no identities and sends nothing, so `signUp` says the address is taken.
- **Tenancy:** one account = one studio. Every person belongs to exactly one studio (`studio_members.user_id` is the primary key); all studio data carries `studio_id`. A member has a role (`owner | photographer | editor | assistant`, names stay in English) plus GoHighLevel-style permission keys; the owner implicitly has all of them, and `only_assigned` limits a member to cards assigned to them. New users sign up as owners and create their studio at `/onboarding`; team members are created by a `team.manage` member from `/equipo` (auth user via the admin client, membership row through RLS).
- **Permissions in the app:** `getStudioContext()` / `requireStudio()` / `requirePermission()` in `apps/app/lib/studio.ts`. The permission catalog (`apps/app/lib/permissions.ts`) must stay in sync with the `studio_members.permissions` check constraint. UI checks are for UX only — RLS is the real gate.
- **Email:** Resend through `@repo/email` (React Email templates in `packages/email/templates`). `apps/app/lib/email.ts` skips sending until `RESEND_TOKEN` and `RESEND_FROM` are set; always pass an idempotency key. Client emails are automatic notifications: never ask clients to reply — contact goes through the studio's WhatsApp (`studios.whatsapp`, digits only, helpers in `apps/app/lib/whatsapp.ts`). The Resend key is sending-only, so the API can't list or read sent emails; test with `delivered@resend.dev` (labels like `delivered+x@resend.dev` work), never with fake addresses.
- **Storage:** card cover photos live in the private `card-covers` bucket at `<studio_id>/<card_id>/<file>` (RLS on `storage.objects` checks the first folder against `current_studio_id()`). Images are compressed in the browser before upload (`compress-image.ts`) and shown through batched signed URLs. The app sends `Cross-Origin-Embedder-Policy: require-corp`, so any cross-origin image needs `crossOrigin="anonymous"` (the host must send CORS headers, as Supabase Storage does) or the browser blocks it. Removing a card/board must also remove its storage objects.
- **Galleries module (in progress, replaces Pixieset):** one selection gallery per card (`galleries`, `gallery_photos`); the client opens `/g/<token>` without an account (public in `apps/app/proxy.ts`; page in `app/g/[token]`, data and actions with the service role scoped to the gallery found by the token, `app/actions/client-gallery.ts`), picks favourites (extras above `included_count` cost `extra_price`, copied from `studios.extra_photo_price`; no payments) and confirms through the `public.submit_gallery_selection` RPC (service role only: closes the gallery, moves the card to the `submitted` stage, logs it); a first-visit guide uses driver.js (`gallery-tour.ts`, seen-flag in localStorage, popover text is HTML so escape names). The client page is studio-branded: its own metadata (studio name, a session photo, `noindex`) instead of `publicPageMetadata`. Sending (`sendGallery`) opens it 60 days, moves the card to the `sent` stage and emails `gallery-ready` instead of the stage email; while a gallery is open every stage email carries «Elegir mis fotos». Emails and team notice live in `apps/app/lib/gallery-notify.tsx`; the studio copies the picked file names without extension into Lightroom's filename filter. Permissions `galleries.view` / `galleries.manage`; a gallery is visible only when its card is. `board_stages.gallery_role` (`sent`/`submitted`) says where the card moves on send/confirm. Photos live in **Cloudflare R2** (bucket `uphotox-galerias`, env `R2_*`, client in `@repo/storage` = `packages/storage` via `aws4fetch`), not Supabase Storage, at `<studio_id>/<gallery_id>/<photo_id>.jpg` and `_t.jpg` (thumbnail): R2 has no RLS, so the server hands out presigned URLs only after RLS (members) or the token (client, service role scoped to that gallery). Deleting photo rows (directly or by cascade) queues their keys in `storage_deletions` via trigger; any action that deletes photos, galleries, cards, boards or clients must call `scheduleStorageCleanup()` (`apps/app/lib/storage-cleanup.ts`), and a daily job sweeps the rest. The browser uploads straight to R2 with presigned PUTs (`prepareGalleryUploads` → PUT → `confirmGalleryUploads`, which checks the objects exist); download URLs are signed per UTC day so they stay cacheable. Pure rules (state, package from notes, Lightroom list, extras) live in `apps/app/lib/gallery.ts` (tested). Link expires 60 days after sending; photos are purged 60 days after confirmation/expiry, rows kept. Setup and CORS: `docs/cloudflare-r2.md` (add any new app domain to the bucket's CORS).
- **Editor module (in progress), `services/editor` and `tools/fondo-lab`:** first Editor task = AI backdrop/floor clean-up that never touches people. Runs on **Cloudflare** (the R2 account; user wants no new platforms): `services/editor` is a standalone project (not an npm workspace, so Vercel installs never pull wrangler/onnxruntime) with a Worker (`src/index.ts`: `POST /photos` with Bearer `EDITOR_TOKEN` → Queue → consumer streams the R2 original to an `Engine` container and stores `result/preview/zones.jpg`, `info.json`, `status.json` next to it; R2 via binding, so the container has only the AI keys) and the engine (`engine/`, Dockerfile, Node + sharp + onnxruntime-node; `lib/pipeline.mjs` `cleanPhoto` = one photo end to end, retries on API errors/reframing, keeps EXIF + ICC). Live at https://uphotox-editor.osvaldo-ac2.workers.dev (Workers Paid; `EDITOR_URL` / `EDITOR_TOKEN` in `apps/app/.env.local`, secrets `EDITOR_TOKEN`, `GEMINI_API_KEY`, `OPENAI_API_KEY` on the Worker), built and deployed by Cloudflare Workers Builds from `main` with root `services/editor` (no Docker on the dev PC; `wrangler deploy --dry-run --containers-rollout=none` bundles the Worker only); `npm run try` there tests one photo end to end; setup in `services/editor/README.md`. `tools/fondo-lab` is the multi-model lab and imports the engine's `lib/` (one copy of the pipeline; `npm run lab -- --fotos <folder>` reads keys from `apps/app/.env.local`: `GEMINI_API_KEY`, `OPENAI_API_KEY`). Pipeline: analysis + zones (Gemini Flash JSON) → person mask (MODNet ONNX; models in `services/editor/engine/models/`, git-ignored) → edits (Nano Banana 2/Pro via `generateContent`, `gpt-image-2` via `/images/edits`) → `lib/composite.mjs` (align, colour-match, full-res with sharp; people — original and model-drawn silhouettes — and props it merely redrew stay original; `--modo completo`, the default, takes the rest of the background whole with a low-frequency colour field; `zonas` only uses fix boxes, which leaves seams on plain backdrops; a "helper" box — a parent's hand holding the child — is the one part of a person taken from the model, never inside the zones step's face boxes) → Gemini review → optional framing (`--encuadre <model>`, `lib/framing.mjs`: tilt from Hough lines of the backdrop, crop from Gemini shown the studio's own crops recovered from `editadas/`, applied with sharp; image models never reframe) → `resultados-ia/informe.html` (blind vote). Decided: GPT Image 2, only the photos the client picks in the gallery. In the app: `edit_photos` (one per picked gallery photo; status/score/comment written only by the server with the admin client from the service's `status.json`; members insert and delete through RLS with `editor.access`) and `edit_usage` (cost per run, unique photo+run, kept when photos go: the studio's consumption); R2 `editor/<studio_id>/<gallery_id>/<edit_photo_id>/` (`@repo/storage/editor`, mirrored by the `edit_photos_queue_deletion` trigger). Actions in `app/actions/editor.ts` (`prepareEditUploads` → browser PUT → `confirmEditUploads` queues in the Worker → `refreshEditPhotos`, polled by the page), pure rules in `lib/editor.ts` (tested), service client in `lib/editor-service.ts` (`EDITOR_URL`, `EDITOR_TOKEN`). Pages: `/editor` (month consumption, galleries) and `/galerias/[id]/limpieza` (review cards: hold for `before.jpg`, zones, approve / redo with a note / discard; download of approved ones into the session folder via File System Access as `<name>-fondo.jpg`). The Worker calls back `POST /api/editor/callback` (public in `proxy.ts`, Bearer `EDITOR_TOKEN`; `lib/editor-sync.tsx` syncs and emails «Fotos limpias listas» when a gallery has nothing left in the cloud). Studio settings `editor_helpers`, `editor_framing` (engine `styleFraming`: tilt + the studio's average trims, no AI), `editor_monthly_limit` (checked when queueing), `editor_keep_days` (daily `GET /api/cron/purge` in `apps/app/vercel.json`, needs `CRON_SECRET`). Each photo has a mode (`fondo`: backdrop and floor, people original, composite `completo`; `completa`: everything but the faces of those who stay, composite `rostros`, `fullEditPrompt`), a demand level (1 one model; 2 GPT Image 2 and Nano Banana Pro in parallel, the reviewer keeps the best; 3 plus a second pass on what the reviewer still saw wrong) and, at level 1, a model (`gpt` / `nbpro`); stored in `edit_photos.mode/level/model` (`winner` from `info.chosen`), studio defaults `studios.editor_mode/level/model`, chosen with `components/edit-choice-fields.tsx` when uploading, redoing and in Ajustes; cost estimates in `lib/editor.ts` (`estimatedCost`). No cost confirmation before starting (user's choice): consumption is shown instead. Plan: `docs/plan-editor.md`. Client photos and outputs stay outside the repo. sharp gotchas: one pipeline applies each op once in its own order (chain mask steps as separate calls) and `greyscale()` keeps three bands (use `extractChannel(0)`).
- **Inbound webhook (API app):** `POST {NEXT_PUBLIC_API_URL}/webhooks/clients/<token>` in `apps/api` turns a form response (Typeform via Make, Zapier, n8n…) into a client + card. The secret URL token lives in `studio_integrations`; the route uses the service-role client, so every write must be scoped to the integration's studio. Pure parsing lives in `apps/api/lib/inbound-client.ts` (tested). It never emails the client.
- **Clients module and CSV import:** `/clientes` lists clients with their cards; `/clientes/importar` turns a CSV of already-booked clients into cards in a chosen stage. Parsing, column guessing, date reading and row checks are pure code in `apps/app/lib/csv.ts` + `apps/app/lib/client-import.ts` (tested, run in the browser for the live preview); the server action calls the `public.import_cards` RPC (security invoker, one transaction): it reuses a client with the same email (case-insensitive) or phone digits, sets `cards.source = 'import'`, and skips rows whose `external_id` already exists (the file's ID column, or a `csv:` hash), so re-importing is safe. Importing never emails anyone. A session at 00:00 local means "day only" (`lib/session-date.ts`). Boards accept `?tarjeta=<id>` to open a card.
- **Deployment:** Vercel team «Upgradix's projects» (`team_p2pDyMRIYHOPuQVg5hAbJUGw`, Hobby): project `uphotox-app` (root `apps/app`, https://uphotox-app.vercel.app) and `uphotox-api` (root `apps/api`, https://uphotox-api.vercel.app), both linked to GitHub `main`, so every push deploys (unchanged projects are skipped; `[skip ci]` in the commit message skips the build). Env vars live in each Vercel project; `NEXT_PUBLIC_*` changes need a redeploy. Vercel builds with `NODE_ENV=production`, so `apps/app/vitest.config.mts` forces `NODE_ENV=test`. The Vercel MCP connection only sees the personal account; use the CLI (`vercel api …?teamId=…`) for the team. On Windows, quote CLI URLs containing `&`. Guide: `docs/deploy-vercel.md`.
- **Brand:** symbol + wordmark via `apps/app/components/brand-logo.tsx` (light/dark symbol PNGs in `apps/app/public/brand`); favicon `app/icon.png`, iOS `app/apple-icon.png`, PWA `app/manifest.ts` + `public/brand/icon-*.png`. Link-preview title, description and image (`public/brand/og.jpg`, keep it under ~300 KB for WhatsApp) live in `apps/app/lib/metadata.ts`: the root layout uses `rootMetadata`, public pages must use `publicPageMetadata` (crawlers without a session always land on `/sign-in`). Masters and guide in `docs/brand/`. Client emails stay studio-branded (no Uphotox logo). No Chinese/Japanese characters anywhere.

## Database rules

- Every table in `public` gets, in the same migration: RLS enabled, `revoke all … from anon, authenticated`, explicit (column-level where sensible) grants, and policies scoped `to authenticated`. Studio data checks `studio_id = (select private.current_studio_id())` plus `(select private.has_permission('…'))`; use `(select private.only_assigned())` where assignment applies. Update policies need both `using` and `with check`.
- Keep related rows in one studio with composite foreign keys (`(board_id, studio_id) → boards (id, studio_id)` etc.) and give each composite FK a covering index.
- Index foreign keys and columns used in policies.
- Helper functions go in the `private` schema with `set search_path = ''`. Revoke `execute` from `public, anon`; trigger functions also from `authenticated`. The RLS helpers (`current_studio_id`, `has_permission`, `only_assigned`) are `security definer` and granted to `authenticated` because policies call them as the querying role. Avoid `security definer` anywhere else unless required.
- Never use `user_metadata` for authorization. Use the admin client (secret key, bypasses RLS) only in trusted server code, after checking the caller's permission.

## Commands

- `npm run dev -- --filter=app` — main app on :3000
- `npm run build -- --filter=app --filter=api` — builds and runs tests first
- `npm run check` / `npm run fix` — Ultracite (Biome)
- Env vars live in `apps/*/.env.local`; each package validates its own in `keys.ts`, and empty strings count as unset.
